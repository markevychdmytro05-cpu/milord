# Перевірка реального додавання в кошик — 26.09.2026

Перевірку виконано на прохання користувача у вже відкритому профілі AdsPower №7.

## Сценарій

- Використано поточні `AdsPowerClient`, `AdsPowerProvider`, `runTask`, `realClock` і `Store`.
- Ядро запущено діагностичним скриптом зі сховищем `.local-data/live-cart-test.json`.
  Це не було створенням завдання через UI; інтерфейс перевірено окремо.
- Товар: «Архістратиг Михаїл (c)», product ID 1126.
- Ціна на момент тесту: 4 969 грн; початкова кількість у формі — 1.
- Вхід в акаунт розпізнано, кнопка «Купити» доступна, товар ще не був у кошику.

## Результат

- Одне оновлення сторінки та одна спроба натискання.
- Після натискання коротко з’явилася перевірка сайту. Програма призупинила дії;
  перевірка завершилася автоматично, без ручного втручання чи обходу.
- Приблизно через 7 секунд після натискання ядро отримало стан `in_cart`.
- На товарній сторінці: «В кошику», лічильник — 1.
- У модальному кошику: «Архістратиг Михаїл (c)», загальна сума — 4 969 грн.
- Товар залишено в кошику для користувача. Оформлення та оплата не виконувалися.
- Від’єднання Playwright залишило AdsPower-профіль відкритим.

## Що з’ясувалося

- Local API доступний без ключа в поточній локальній конфігурації.
- API переліку всіх профілів повертає обмеження тарифу. Це не завадило підключенню
  до конкретного відкритого профілю та сценарію покупки.
- Номер профілю в інтерфейсі AdsPower і внутрішній ID — різні значення. Поточна форма
  NBU Desktop очікує внутрішній ID.
- Кошик магазину відкривається обробником `.popup_cart` як модальне вікно.
  Пряма навігація на `shopping_cart.php` повернула 404; перевірка проведена через
  штатну кнопку кошика. Ядро покупки не використовує цю пряму навігацію.

Не перевірено цим тестом: старт нового дефіцитного продажу, тривала черга, ручна капча,
перезапуск AdsPower, зміна версії браузера та оформлення замовлення.
