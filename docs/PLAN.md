# План створення NBU Desktop

Мета: окрема десктопна програма для запланованого додавання монет НБУ в кошик через
профіль AdsPower. Перший цільовий комп’ютер — macOS; код готується до Windows.
Програму можна запускати з вихідного коду; підписані інсталятори — окремий етап.

## 1. Основа проєкту — реалізовано

- TypeScript, Electron, React, збірка esbuild і зафіксовані залежності npm.
- Ізольований інтерфейс, обмежений preload API, перевірка джерела IPC.
- Один екземпляр програми; локальні завдання та журнал; системні сповіщення.
- Захист від автоматичного сну ОС, поки є заплановані або активні завдання.
  Закрита кришка ноутбука, примусовий сон і вимкнення комп’ютера все одно переривають роботу.

Критерій приймання: `npm run check`, запуск вікна без AdsPower, створення та скасування завдання.

Перевірено 26.09.2026: типи, 33 тести, збірка та UI smoke-тест пройшли.
Вікно запускалося; налаштування зберігалися; майбутнє завдання створювалося та скасовувалося.
Реальні запити до AdsPower і НБУ в ці перевірки не входили.

## 2. Перенесення сценарію з GitHub — реалізовано

Джерело: `cookieMonsterDev/nbu-store-speed-buyer`, commit
`fc0e22e23938078e3f09f7db88cba90c4a78731f`. Оригінали та MIT-ліцензія збережені в `third-party/`.

- Підготовка сторінки за N хвилин до продажу.
- Оцінка різниці локального та серверного часу через три HEAD-запити.
- Оновлення на старті продажу, повторна перевірка доступності кнопки.
- Максимум 5 спроб натискання, щонайменше 11 секунд між ними.
- Очікування черги без перезавантажень після кліку.
- Виявлення кошика, перевірки браузера та потреби в авторизації.
- Обмежене очікування результату після кліку — 120 секунд.
- Режим спостереження, який не натискає кнопку покупки.

Критерій приймання: тести сценарію, включно зі скасуванням, збоєм запису на диск,
невизначеним результатом і забороною автоматичного повтору після перезапуску.

## 3. AdsPower — адаптер реалізовано; базовий реальний сценарій перевірено

26.09.2026 модулі `AdsPowerProvider` і `runTask` успішно додали одну доступну монету
в кошик у відкритому профілі користувача. Підтверджено назву товару та суму в модальному
кошику. Оформлення замовлення й оплата не виконувалися. Деталі — [LIVE_TEST.md](LIVE_TEST.md).
Тест реального магазину запускав ядро програми окремим діагностичним скриптом;
створення завдання через десктопний інтерфейс перевірене окремим UI smoke-тестом.

- Запуск Chromium/SunBrowser-профілю через Local API v1.
- Підключення Playwright через повернений CDP endpoint.
- Використання наявного browser context і збереженої сесії.
- Список профілів із пошуком через Local API, вибір кількох профілів, перевірка без покупки.
- Від’єднання автоматизації зі збереженням браузера відкритим для користувача.
- Взаємне виключення завдань, що перетинаються в одному профілі.
- API-ключ зберігається зашифрованим через safeStorage; підтримка `ADSPOWER_API_KEY`.

Для приймання потрібен встановлений AdsPower із доступом до Local API та профіль користувача:

1. Перевірити запуск і підключення, повторне використання вкладки та від’єднання.
2. Увійти в акаунт НБУ, повторити перевірку профілю.
3. Перевірити стан сторінки й за потреби скоригувати селектори під актуальний сайт.
4. Запланувати режим спостереження на доступному товарі; підтвердити нуль натискань.
5. Перевірити ручне проходження перевірки сайту та відновлення спостереження.
6. Окремо провести керовану спробу додавання в кошик і перевірити результат вручну.

AdsPower не гарантує проходження бот-детекції; це приймання обов’язкове перед реальним продажем.

## 4. Локальні дані та відновлення — базова версія реалізована

Початкова версія використовує версійований JSON із послідовними записами через тимчасовий
файл та перейменування. Це не SQLite і не журнал із гарантією `fsync` при раптовій втраті живлення.

- Завдання, які вже виконувалися, після перезапуску стають `interrupted`.
- Заплановані завдання зберігаються; прострочені завершуються без покупки.
- Перед кліком намір записується на диск. За помилки запису натискання не виконується.
- Cookies і пароль НБУ залишаються у профілі AdsPower.

Наступне розширення: SQLite з міграціями, транзакційним журналом і політикою зберігання історії.
API-ключ відновлюється з окремого зашифрованого файла між запусками.

## 5. Доведення інтерфейсу — частково реалізовано

Є: окрема вкладка налаштувань, Inter, список профілів із пошуком, паралельні завдання для кількох профілів, статуси, журнал і незалежне скасування.
Дата й журнал зафіксовані в Europe/Kyiv; типове значення — найближчі 10:00.
Стартовий шлях оптимізовано: без секундної паузи після оновлення та без запису на диск перед ним.
Локальне стеження за кнопкою реагує на зміни DOM; мережеві повтори обмежені мінімумом 5 секунд.

Наступне:

- Окремі повідомлення про недоступний API, вимкнений профіль і зміну сторінки.
- Трей, явне відновлення після сну, показ часу до продажу.
- Обмеження й очищення історії, експорт журналу без секретів.
- Додаткове відображення зміщення годинника й окремих затримок запиту, черги та додавання в кошик.

## 6. Збірки для розповсюдження — заплановано

- Пакування macOS `.dmg` / Windows installer.
- Перевірка залежностей у запакованій програмі, особливо Playwright.
- Підпис і notarization для macOS; підпис Windows за наявності сертифікатів.
- CI: типи, тести, збірка; окремий тест запуску на macOS і Windows.
- Оновлення програми після перевірки базового релізу.

Критерій приймання: встановлення на чистому комп’ютері з AdsPower без Node.js.

## 7. Можливі наступні функції — окрема розробка

- Адаптер звичайного Chrome зі спільним ядром сценарію.
- Моніторинг появи монет, незалежний від фіксованого часу продажу.
- Оформлення замовлення після кошика: дослідити форми, доставку, кількість і підтвердження;
  цього сценарію немає у вихідному репозиторії.
- Автоматична оплата не реалізована. Платіжний сценарій потребує окремого проєктування.

## Технічні межі поточного перенесення

- Автоматизація працює, поки відкриті NBU Desktop і AdsPower.
- Розклад виконується у головному процесі Electron; важких обчислень у ньому немає.
  За розширення сценаріїв можна винести виконання в окремий utility process.
- Видиме вікно браузера залишається окремим вікном AdsPower.
- Зміна URL користувачем припиняє сценарій; після ручного входу треба повернутися до товару.
- Очікування `needs_attention` не обходить капчу, чергу чи обмеження магазину.
- Оцінка часу через HTTP Date має секундну точність; мережева затримка також впливає на старт.
- Не слід одночасно запускати вихідне розширення та цей сценарій у тому самому профілі.
