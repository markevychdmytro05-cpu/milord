# NBU Desktop

Початкова десктопна програма на TypeScript + Electron + React для роботи з магазином
монет НБУ через профіль AdsPower. Логіку додавання в кошик адаптовано з
[nbu-store-speed-buyer](https://github.com/cookieMonsterDev/nbu-store-speed-buyer).

**Це робоча основа для запуску з вихідного коду.** 26.09.2026 перевірено реальне додавання
однієї монети в кошик через відкритий профіль AdsPower. Сценарій старту дефіцитного продажу
та довгої черги ще не перевірено. Інсталятора поки немає.

## Запуск

Потрібні Node.js 20.19+ та AdsPower із доступом до Local API і Chromium/SunBrowser-профілем.

```sh
cd nbu-desktop
npm ci
npm start
```

1. Відкрийте AdsPower, увімкніть Local API та скопіюйте його адресу/ключ.
2. У вкладці «Налаштування» збережіть адресу на кшталт `http://127.0.0.1:50325` та ключ.
   Використовуйте `127.0.0.1` або `localhost`, якщо AdsPower показує `local.adspower.net`.
3. У «Налаштуваннях» додайте профілі: ID з AdsPower та зручну назву. Збережіть налаштування. У «Завданнях» оберіть потрібні профілі зі списку й введіть посилання на монету. Натисніть «Перевірити профілі».
4. За потреби увійдіть в акаунт НБУ у відкритому браузері. Поверніться до сторінки монети.
5. Заплануйте **«Спостерігати без покупки»** на кілька хвилин уперед. Якщо кнопка доступна,
   завдання завершиться статусом «Кнопку знайдено», без натискання.
6. Для додавання в кошик створіть завдання з відповідним режимом.

Режим «Додати монету в кошик» виконує реальні натискання. Після успіху оформлення та
оплата залишаються у вікні AdsPower. Капча, якщо з’явиться, потребує вашої участі.

## Час і швидкість старту

- У формі та журналі завжди **Europe/Kyiv**, незалежно від налаштувань комп’ютера.
  За замовчуванням запропоновано найближчі 10:00 за Києвом; сезонне переведення враховується.
- Профіль і сторінка готуються заздалегідь. До старту немає циклічних оновлень сторінки.
  Підготовка включає три HEAD-запити для оцінки серверного часу.
- Стартове оновлення чекає і локального дедлайну, і обережної оцінки часу сервера.
  HTTP Date має точність до секунди: ця стратегія може трохи запізнитися, зате оцінка не
  округлюється вперед. Застарілий заголовок Date, черга чи затримка сервера не дають гарантії точного старту.
- Після завантаження HTML кнопка перевіряється одразу. Далі MutationObserver реагує на зміни
  сторінки локально, без запитів до НБУ; кадри браузера покривають зміни видимості через CSS.
- Якщо кнопки немає й немає черги/перевірки, повторне оновлення — не раніше заданого інтервалу,
  щонайменше через 5 секунд після завершення попереднього завантаження. Секундної серії запитів немає.
- Якщо сервер ще не додав кнопку в HTML і сайт сам не змінює сторінку, локальний спостерігач
  її не створить: тоді потрібне наступне оновлення. Після першого кліку оновлення припиняються.
- Запис наміру на диск перед кліком збережено, щоб збій не спричинив повторну покупку.

`npm run benchmark` вимірює реакцію на локальній HTML-сторінці в установленому Chrome.
До НБУ або AdsPower цей тест не підключається; результат пишеться в `.local-data/benchmark.json`.

Поки виконується завдання, залишайте програми відкритими та не закривайте кришку ноутбука.
У профілі має бути одна вкладка магазину; вимкніть іншу автоматизацію покупки в цьому профілі.
Зміна товарної сторінки під час виконання зупиняє сценарій.

## Секрети й дані

- Ключ AdsPower можна ввести в інтерфейсі або передати через `ADSPOWER_API_KEY`.
  `.env` автоматично не завантажується. Ключ не записується у файл завдань.
- Ключ із налаштувань зберігається у `adspower-key.enc` через Electron safeStorage та відновлюється після перезапуску. На macOS ключ шифрування захищено Keychain. Незашифрованого резервного збереження немає; Linux basic_text відхиляється.
- Порожнє поле при збереженні залишає попередній ключ; окрема кнопка його видаляє. Якщо встановлено `ADSPOWER_API_KEY`, після видалення використовується він.
- Завдання та події зберігаються в `tasks.json` у каталозі `app.getPath('userData')` Electron;
  типовий шлях macOS: `~/Library/Application Support/NBU Desktop/`.
- Пароль і cookies НБУ програма не імпортує: використовується сесія профілю AdsPower.
- Завдання зі спробою виконання після збою не перезапускаються самі. Перевірте кошик
  перед створенням нового завдання.
- «Зупинити» припиняє подальші дії, але не видаляє товар, який уже потрапив у кошик.

## Перевірка коду

```sh
npm run check
```

Команда перевіряє типи, запускає тести та збирає Electron main/preload/renderer.
Тести ядра використовують керований годинник і фальшивий браузер; не звертаються до НБУ
чи вашого AdsPower й не виконують реальних покупок.

Перевірки включають TypeScript, сценарії покупки, стартовий дедлайн, київський час,
сезонні переходи, браузерний спостерігач, збірку та запуск Electron-вікна.
Окремий `npm run test:ui` відкриває програму з тимчасовим сховищем, перевіряє налаштування,
завантаження профілів із локального тестового API, створення й незалежне скасування двох завдань, шрифт Inter і відновлення/видалення ключа після перезапуску. Часовий пояс тестової програми
встановлений в America/Los_Angeles, щоб перевірити незалежність київського часу. До AdsPower він не підключається.

```text
src/core/          сценарій покупки, типи, перевірка введених даних
src/browser/       AdsPower API, Playwright, розпізнавання сторінки НБУ
src/main/          Electron, локальне сховище, планувальник, IPC
src/renderer/      React-інтерфейс українською
tests/             перевірки сценаріїв, API, розкладу та відновлення
third-party/       джерело перенесеної логіки та MIT-ліцензія
```

## Кілька профілів

Власний список профілів зберігається локально в налаштуваннях: ID та необов’язкова назва. Він працює без ключа й без запиту списку до API. У завданнях доступний вибір одного або кількох збережених профілів. Повторювані ID відхиляються; попередні запам’ятовані ID переносяться автоматично.

За бажанням у налаштуваннях можна розгорнути «Імпорт через API AdsPower» та завантажити доступні профілі через [Query Profile](https://localapi-doc-en.adspower.com/docs/u8m2Ie). Помилка тарифу не впливає на локальний список. Керування браузерами залишається залежним від доступності Local API у поточній конфігурації AdsPower.

Для кожного обраного профілю створюється незалежне завдання на один час продажу. Конфлікт одного профілю відхиляє весь новий набір. Підготовчі звернення до Local API рознесені на 1,1 с відповідно до [обмежень AdsPower](https://localapi-doc-en.adspower.com/docs/Rdw7Iu); після підключення профілі очікують дедлайн паралельно. Реальний одночасний продаж у кількох профілях ще не перевірено.

Inter включено локально: завантаження шрифту з інтернету не потрібне.

## Кілька монет в одному профілі

У формі завдання натисніть «Додати монету» для додаткових посилань. Один спільний час старту задається за Києвом; монети виконуються в порядку полів зверху вниз для кожного обраного профілю. Наприклад, 2 монети × 2 профілі створять 4 завдання.

У межах одного профілю одночасно виконується одне завдання, щоб не створювати зайві вкладки магазину й не переривати чергу. Різні профілі працюють паралельно. Наступна монета стартує після завершення попередньої в тому самому профілі. Усі монети мають спільне вікно очікування від заданого часу продажу: якщо перша витратить усе вікно, наступні завершаться як прострочені. Найважливішу монету ставте першою.

Після збою, невідомого результату або скасування попередньої монети решта цієї послідовності зупиняється. Перевірте кошик перед створенням нового запуску. Послідовність зберігається після перезапуску; перервана покупка не запускається повторно. Максимум 200 завдань за один запуск. Автоматичне оформлення чи оплата не додавалися.
